# 要件書：社内報システム（v1）

社長より。わが社の最初の仕事は、わが社の社内報を作ることです。

## 目的

組織（PM・エンジニア・レビュアー・社長）の GitHub 上の活動から、**日報**と**月刊社内報**を自動生成する。
社内報は外部（note / Qiita / X）にも公開する読み物なので、正確さと面白さの両方が必要。

## 出力

| 種類 | コマンド | 出力先 |
|------|----------|--------|
| 日報 | `npm run newsletter -- daily 2026-11-07` | `issues/daily/2026-11-07.md` |
| 月刊社内報 | `npm run newsletter -- monthly 2026-11` | `issues/monthly/2026-11.md` |

- `--dry-run`：LLM を呼ばず、集計結果（facts）だけを標準出力に JSON で出す
- 日付・月の区切りは Asia/Tokyo 基準

### 日報の内容
社員ごと（竹中官兵衛・藤堂秀吉・大岡三成・織田家康）に、その日やったことを各キャラの文体で数行。活動がない社員は「本日の活動なし」とだけ書く。

### 月刊社内報の内容
1. 巻頭言（竹中官兵衛）
2. 今月の数字（表）
3. 今月の出来事（エスカレーション・3回差し戻しなどの「事件簿」）
4. 今月のMVP指摘（大岡三成が選ぶ）
5. 社長の返信待ち時間ランキング
6. 編集後記

## データソース

- 対象リポジトリは `company.config.json` の `repos`（例：`["masakiShito/ai-company-hq"]`）で設定する
- 取得は `gh api` 経由。取得対象：Issue、Issue コメント、PR、PR レビュー、レビューコメント、Issue の timeline（ラベル変更イベント）
- 取得した生データは `data/raw/`（git 管理外）にキャッシュしてよい
- 発言者の判定：PR レビューと `pm`/`reviewer` の区別は、コメント本文やラベル操作の文脈から判断できる範囲でよい。判定できないものは「組織」として扱う。判定ルールはコードとテストで明示する

## 指標（すべてコードで計算する）

- 期間内に作成・クローズされた Issue 数
- 作成・マージされた PR 数
- 初回レビューでの承認率（エンジニアのプライド）
- PR あたりの平均差し戻し回数
- Issue のリードタイム（作成 → クローズ）の中央値
- `status:question` が付いていた時間の合計と最長（＝社長の返信待ち）
- エスカレーション件数

## 最重要：事実と語りの分離

LLM は存在しない PR や差し戻しを平気で創作する。これを構造的に防ぐ。

1. **collect**：GitHub から取得 → 正規化したイベント列にする
2. **metrics**：イベント列から指標と出来事候補を計算する（純粋関数、テスト必須）
3. **facts**：LLM に渡す唯一の入力を JSON で作る（指標・出来事・Issue/PR の番号とタイトル）
4. **write**：facts とキャラ設定（`characters/`）だけを `claude -p` に渡して本文を書かせる
5. **verify**：生成された本文を検証する
   - 本文中の `#番号` がすべて facts に存在すること
   - 「今月の数字」の表は LLM に書かせず、コードで生成して差し込むこと
   - 検証に失敗したら1回だけ再生成し、それでも失敗したらエラー終了（嘘を含む社内報は出さない）

## キャラ設定

`characters/*.md` を読み込んでプロンプトに含める。キャラは語り口にだけ効き、事実を変えない（`characters/README.md` の共通ルール）。

## 非機能

- `claude -p` と `gh` は差し替え可能なインターフェースにし、テストではモックする
- 実行に必要なのは `gh` の認証と Claude Code のみ。API キーをリポジトリに置かない

## スコープ外（v1 ではやらない）

- 朝会議事録
- note / GitHub Pages への自動公開
- Web UI
- Codex のセッションログの取り込み
- 定期実行（cron / GitHub Actions）

## 受け入れ条件（全体）

- [ ] `npm run newsletter -- monthly <月> --dry-run` で facts が JSON で出る
- [ ] `npm run newsletter -- monthly <月>` で `issues/monthly/<月>.md` が生成される
- [ ] `npm run newsletter -- daily <日付>` で `issues/daily/<日付>.md` が生成される
- [ ] facts に存在しない `#番号` を含む本文は出力されない（テストで確認）
- [ ] 指標の計算にユニットテストがある
- [ ] README に使い方が書かれている
